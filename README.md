# ระบบจัดการสต็อกอุปกรณ์ไอที (Hardware Stock Management System)

ระบบบริหารคลังอุปกรณ์ไอทีแบบครบวงจร ทดแทนการบันทึกด้วยไฟล์ Excel รายเดือน
รองรับ **การรับอุปกรณ์เข้า (IN)**, **การเบิกออก (OUT)**, **การรับคืน**, **การปรับปรุงสต็อก**,
การติดตามทรัพย์สินรายชิ้นด้วย Serial และรายงานรูปแบบเดียวกับไฟล์เดิม

---

## คุณสมบัติหลัก

### 📥 รับอุปกรณ์เข้าคลัง
- บันทึก วันที่รับ, เลขที่ PO, ผู้ขาย, รายการอุปกรณ์ และราคาต่อหน่วย
- อุปกรณ์ที่ติดตามรายชิ้น กรอก Serial ได้ทีละหลายรายการ ระบบ**นับจำนวนให้อัตโนมัติ**
  จึงไม่มีทางที่จำนวนกับ Serial จะไม่ตรงกัน
- เลขที่เอกสารออกอัตโนมัติ `IN-2569-0001` แยกตามปี

### 📤 เบิกอุปกรณ์ออก
- บันทึกครบตามไฟล์เดิม: วันที่, ผู้เบิก (รหัส - ชื่อ / แผนก), Desktop / Laptop / Accessories,
  เจ้าหน้าที่ IS, สถานะ Charge (Y/N) และ Remark
- เลือก Serial จาก**เฉพาะของที่มีอยู่ในคลังจริง** — เบิกซ้ำหรือเบิกของที่ถูกเบิกไปแล้วไม่ได้
- ตรวจยอดคงเหลือก่อนบันทึกเสมอ เบิกเกินสต็อกระบบจะปฏิเสธพร้อมบอกยอดที่เหลือจริง

### ↩️ รับคืนอุปกรณ์
- เลือกผู้คืนแล้วระบบกรอง Serial ที่บุคคลนั้นถือครองอยู่มาให้
- แยกสภาพ **ใช้งานได้** (คืนเข้าคลัง เพิ่มยอด) กับ **ชำรุด** (ตัดจำหน่าย ไม่เพิ่มยอด)

### ⚖️ ปรับปรุงสต็อก
- ใช้บันทึกผลการตรวจนับ ของหาย ของเกิน พร้อมแสดงยอดใหม่ให้เห็นก่อนบันทึก
- ระบบไม่ยอมให้ปรับจนยอดติดลบ

### 🏬 ระบบเช็คข้อมูลคลัง
- ยอดคงเหลือพร้อมตัวกรอง (หมวดหมู่, ใกล้หมด, หมดคลัง, มีของ) และการเรียงลำดับ
- **การ์ดสต็อก** รายอุปกรณ์ แสดงยอดสะสม (running balance) ทุกการเคลื่อนไหว
- **ทะเบียนทรัพย์สิน** ค้นหาได้ว่า Serial ไหนอยู่ที่ใคร แผนกอะไร พร้อม**ไทม์ไลน์**ทั้งชีวิตของอุปกรณ์ชิ้นนั้น
- แจ้งเตือนของใกล้หมดบนเมนูและแดชบอร์ด

### 📈 รายงาน
| รายงาน | รายละเอียด |
|---|---|
| รายเดือน (รูปแบบเดิม) | ตาราง IN และ OUT หน้าตาเดียวกับไฟล์ Excel เดิม แยกคอลัมน์ Desktop / Laptop / Accessories |
| สรุปตามแผนก | จำนวนใบเบิก จำนวนชิ้น มูลค่า แยก Charge Y/N |
| สรุปตามหมวดหมู่ | รับเข้า จ่ายออก คงเหลือ และมูลค่า |
| อุปกรณ์ที่เบิกบ่อย | จัดอันดับอุปกรณ์ที่ถูกเบิกมากที่สุด |
| ทรัพย์สินที่ถือครอง | พนักงานแต่ละคนถืออุปกรณ์อะไรอยู่บ้าง |
| สรุปค่าใช้จ่าย | มูลค่าที่ต้องเรียกเก็บ (Charge = Y) แยกตามแผนก |
| บันทึกการใช้งาน | ใครทำอะไรกับระบบเมื่อไหร่ |

ทุกรายงานส่งออก **CSV พร้อม BOM** เปิดใน Excel แล้วภาษาไทยไม่เพี้ยน และสั่งพิมพ์ได้

### 🔐 ผู้ใช้งานและสิทธิ์
| สิทธิ์ | ทำอะไรได้ |
|---|---|
| `admin` ผู้ดูแลระบบ | ทุกอย่าง รวมถึงจัดการผู้ใช้และลบข้อมูลหลัก |
| `officer` เจ้าหน้าที่คลัง | บันทึก/ยกเลิกเอกสาร และเพิ่มแก้ไขข้อมูลหลัก |
| `viewer` ผู้ดูข้อมูล | ดูข้อมูลและรายงานอย่างเดียว |

รหัสผ่านเข้ารหัสด้วย `scrypt` เซสชันเป็น signed cookie (HttpOnly) และมีบันทึก audit log

## เริ่มใช้งาน

```bash
npm install          # ติดตั้งไลบรารี
npm run seed         # สร้างฐานข้อมูล + ผู้ดูแลระบบเริ่มต้น
npm start            # เปิดเซิร์ฟเวอร์ที่ http://localhost:3000
```

ต้องการข้อมูลตัวอย่างสำหรับทดลอง (อ้างอิงจากไฟล์ HARDWARE REQUEST 2026):

```bash
npm run seed:demo    # เพิ่มข้อมูลตัวอย่าง
npm run reset        # ลบฐานข้อมูลเดิมแล้วสร้างใหม่พร้อมข้อมูลตัวอย่าง
```

**บัญชีเริ่มต้น** — ผู้ใช้ `admin` รหัสผ่าน `admin1234` (⚠️ เปลี่ยนทันทีหลังเข้าใช้งานครั้งแรก ผ่านปุ่ม 🔑 มุมขวาบน)

### การตั้งค่า

คัดลอก `.env.example` เป็น `.env` หรือกำหนดเป็น environment variable:

| ตัวแปร | ค่าเริ่มต้น | ความหมาย |
|---|---|---|
| `PORT` | `3000` | พอร์ตที่เซิร์ฟเวอร์ทำงาน |
| `DB_FILE` | `./data/stock.db` | ตำแหน่งไฟล์ฐานข้อมูล SQLite |
| `SESSION_SECRET` | *(ค่าสำหรับพัฒนา)* | **ต้องตั้งค่าเองก่อนใช้งานจริง** ใช้เซ็น session cookie |
| `ADMIN_PASSWORD` | `admin1234` | รหัสผ่าน admin ตอนสร้างฐานข้อมูลครั้งแรก |

### ทดสอบระบบ

```bash
npm test             # ชุดทดสอบ 41 รายการ (ตรรกะสต็อก + API)
```

## หลักการออกแบบที่ควรรู้

**ยอดคงเหลือคำนวณจากบัญชีเดินสต็อก (ledger) เสมอ**
ตาราง `stock_moves` บันทึกทุกการเคลื่อนไหวเป็นค่าบวก/ลบ ยอดคงเหลือ = ผลรวมของรายการทั้งหมด
ไม่มีการเก็บตัวเลขคงเหลือไว้ซ้ำในที่อื่น ยอดจึงไม่มีทางเพี้ยนจากกัน

**การยกเลิกเอกสารใช้วิธีกลับรายการ ไม่ใช่การลบ**
เอกสารที่ยกเลิกยังอยู่ในระบบพร้อมเหตุผลและผู้ยกเลิก ระบบจะสร้างรายการกลับทางให้
และคืนสถานะ Serial กลับเป็นค่าก่อนหน้าโดยอ้างอิงจากตาราง `serial_events`
หากมีเอกสารอื่นทำต่อจากเอกสารนั้นแล้ว ระบบจะปฏิเสธพร้อมบอกว่าต้องยกเลิกใบไหนก่อน

**ทุกการบันทึกอยู่ใน transaction เดียว**
ถ้ามีบรรทัดใดผิดพลาด ทั้งเอกสารจะไม่ถูกบันทึกเลย ไม่มีเอกสารค้างครึ่ง ๆ กลาง ๆ

**ของชำรุดที่รับคืนจะไม่ถูกนับกลับเข้าคลัง**
บันทึกไว้ในใบรับคืนและเปลี่ยนสถานะ Serial เป็น "ตัดจำหน่าย" แต่ไม่เพิ่มยอดคงเหลือ

## API หลัก

ทุก endpoint อยู่ใต้ `/api` และต้องเข้าสู่ระบบก่อน (ยกเว้น `/api/health` และ `/api/auth/login`)

| Method | Endpoint | หน้าที่ |
|---|---|---|
| `POST` | `/auth/login`, `/auth/logout`, `/auth/change-password` | จัดการเซสชัน |
| `GET/POST/PUT/DELETE` | `/items`, `/categories`, `/departments`, `/employees`, `/is-staff`, `/suppliers` | ข้อมูลหลัก |
| `GET/POST` | `/receipts`, `/issues`, `/returns`, `/adjustments` | เอกสาร |
| `POST` | `/{เอกสาร}/:id/void` | ยกเลิกเอกสาร |
| `GET` | `/stock/balance`, `/stock/low`, `/stock/moves`, `/stock/card/:itemId` | ข้อมูลคลัง |
| `GET` | `/serials`, `/serials/:id` | ทะเบียนทรัพย์สินและไทม์ไลน์ |
| `GET` | `/reports/monthly`, `/reports/by-department`, `/reports/assets-by-holder`, … | รายงาน |
| `GET` | `/dashboard` | ข้อมูลสรุปหน้าแรก |

เพิ่ม `.csv` ต่อท้าย endpoint ของรายงานเพื่อดาวน์โหลดเป็นไฟล์ เช่น `/api/stock/balance.csv`

## การนำขึ้นใช้งานจริง

1. ตั้งค่า `SESSION_SECRET` เป็นค่าสุ่มที่ยาวพอ และตั้ง `NODE_ENV=production`
2. ให้บริการผ่าน reverse proxy (nginx / IIS) พร้อม HTTPS — คุกกี้จะตั้ง flag `Secure` ให้เอง
3. สำรองไฟล์ `data/stock.db` เป็นประจำ (ใช้ `sqlite3 stock.db ".backup"` ขณะระบบทำงานได้)
4. เปลี่ยนรหัสผ่าน `admin` และสร้างบัญชีแยกให้ผู้ใช้แต่ละคนเพื่อให้ audit log มีความหมาย

ระบบไม่เรียกใช้ทรัพยากรภายนอกใด ๆ จึงใช้งานในเครือข่ายปิด (ไม่มีอินเทอร์เน็ต) ได้ทันที
